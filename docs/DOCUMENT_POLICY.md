# ドキュメント運用方針

関連: [コメント規約](./COMMENT_GUIDE.md) / [バックエンドアーキテクチャ](./BACKEND_ARCHITECTURE.md) / [フロントエンドアーキテクチャ](./FRONTEND_ARCHITECTURE.md)

## 新しい文書を書く前に確認する3つの問い

1. **コードから導出できるか？**

  導出できるもの（フォルダ構成、APIの形、クラス一覧）は書かない

  コード・スキーマ・テストに語らせる

1. **現在形か、過去形か？**

  「今こうなっている」は必ず腐る
  
  「あの時こう決めた」に変換できるなら [DESIGN_NOTES.md](./DESIGN_NOTES.md) へ

1. **1つの文書が1つの目的だけを持っているか？**

    「固定したいもの」と「追従させたいもの」が同じファイルに混在していたら分割する

さらに、書く前に自問する

> この文書は、**誰の**、**どの判断**を変えるのか

答えられない場合は書かない

## 文書の配置表

| 文書 | 役割 | 更新のタイミング | 腐ったときの扱い |
| --- | --- | --- | --- |
| `README.md` | セットアップ手順・起動単位の説明 | `npm run dev` 等の起動フローを変えたとき | 手順自体は npm script で実行可能にしてあるので大きくは腐らない |
| `docs/BACKEND_ARCHITECTURE.md`　`docs/FRONTEND_ARCHITECTURE.md` | 層の禁止事項・依存の向き・判断チャート | 層の責務や依存ルールを変えたとき | モジュール名・フォルダ一覧は書かない（実装から読み取れるため） |
| `docs/COMMENT_GUIDE.md` 系 | コメントの書き方の MUST/MUST NOT | 規約自体を変えたとき | - |
| `docs/BACKEND_API_GUIDE.md` | HTTPエンドポイントの設計ルール | ルールを変えたとき | エンドポイント一覧は書かない（OpenAPIが正） |
| `docs/DESIGN_NOTES.md` | 不可逆な決定の記録（過去形・追記のみ） | 不可逆な決定をしたとき | 方針が変わったら新しい項を追記する |
| `docs/task/*`　`docs/spike/*` | タスク・調査ごとの思考ログ | タスク完了時に1回書く | 実装と食い違っても直さない |

## 新しい文書を作るとき

1. 上の3つの問いで切る
2. 配置表のどれにも当てはまらない場合のみ新規作成する
3. 作る前に、更新トリガー（何をしたら見直すか）を1行決めて、決められない場合は分量を最小限に絞る
